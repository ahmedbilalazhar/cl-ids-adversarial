# What population does the cleaned benchmark represent?

Second audit, 24 October 2026. The conditional original-data audit makes this a material design issue. It is not a model-performance finding.

## 1. Exact input equality is not proof of a duplicated physical event

Two independent network flows can have identical values in the retained 76-feature projection. Different reference classes at the same vector can reflect missing discriminative information, incorrect labels, extraction artifacts or a mixture. A hash/equality check alone cannot determine which explanation is true.

Use the term **ambiguous-input annotation group** for identical inputs with different reference labels. Quarantining it is a declared benchmark selection policy, not proof that every removed record was mislabeled. A content-connected component is stronger than provenance/session isolation. Do not call every T0-linked exclusion a demonstrated leaked or duplicated packet.

The primary proposal deliberately requires session/content disjointness and quarantine. Preserve that design unless prospectively amended, while explaining the population it selects. Known extraction and labeling defects motivate scrutiny but do not turn a feature collision into source-event identity. [Dataset authors' investigation](https://intrusion-detection.distrinet-research.be/CNS2022/).

## 2. Deduplication changes the evaluation unit and class mixture

After selecting one deterministic same-label survivor, the primary bank measures performance on retained canonical representatives. It does not retain the original CSV's flow-frequency distribution. Quarantine and T0 component closure change that mixture further.

Consequences to state explicitly:

- “50% dose” means half of the attacked site's **retained eligible source examples**, not half of the original capture's source rows or traffic volume.
- FAR and precision describe the declared curated bank. “False alerts per 10,000 retained benchmark benign records” is accurate; a production traffic-volume forecast is not.
- The fixed 500-record reservoir has a different effective history fraction after aggressive curation. Capacity comparisons remain within this protocol.
- Original and corrected releases can have different flows, annotation policies, family support and class inventories. A common filename/year does not equal a comparable population.

Keep a stage/family table from raw nonempty records through numeric/metadata exclusions, ambiguous groups, same-label duplicates, T0 closure, split and benign training selection. Include relative exclusions and surviving components. Do not report a single “cleaned dataset size” without its denominator.

## 3. The observed strict-isolation effect is large

Under the explicitly conditional original audit's 120-second operational grouping, Monday-only calibration and conservative retained provenance/content links, surviving unique Hulk and PortScan records are about 1,249 and 1,850 respectively. The source census contains 231,073 and 158,930 raw reference rows. These are different populations; the old large-row poison scenarios cannot be treated as measurements of the revised protocol.

The data audit also reports 60/300-second sensitivity and actual components. These numbers remain conditional on source-specific clock/units/quarantine choices. They are not approved final split sizes, a finding that the removed traffic is invalid, or an argument to relax isolation merely to make an attack stronger.

This effect can alter poisoning fraction, learning difficulty, memory dilution, acquisition gates and runtime. Compute and power planning should use the approved **post-curation** inventory, not the familiar headline CICIDS2017 class counts.

## 4. Quarantine and bridge rules require a visible rationale

The current conditional audit retains established session and content provenance links even when a record is excluded from learning. This conservative closure prevents deleting a bridge solely to manufacture split independence. It can also connect otherwise distinct retained sessions through an excluded ambiguous input and produce substantial additional exclusions.

Distinguish three policies in any data-only sensitivity:

1. Operational sessions built from all parseable source intervals, preserving session membership after row exclusion.
2. Exact-content links among model-eligible records and duplicate provenance.
3. Additional exact-content links through quarantined records and calibration-only observations.

Removing a policy-3 link need not split an actual operational session, but it changes the proposed conservative graph. Document the difference, invariant being protected and realized consequences. Do not label one choice a universal scientific requirement without that argument. The primary policy must be chosen before model outcomes, consistently for every arm.

## 5. Efficient evidence strategy

**Now:** complete data-only exclusion, component and source-exposure comparisons. They are cheaper and more informative than dispatching hundreds of conditions on an unexamined data contract.

**Primary:** run the selected fixed curation protocol, retaining the original RQs and matched controls. Describe conclusions conditional on that curated population.

**If claiming stability to curation:** predeclare one alternative grouping/weighting sensitivity. A DR/DM/DC clean/maximum-dose subset over twelve seeds costs 72 full logical trajectories; all five core arms would cost 120. These are separate benchmark protocols on the same capture, not an independent external replication. Include required clean development/feasibility work and separate bank/protocol identities. Neither is included in the 441/513 bases.

An optional multiplicity-weighted descriptive analysis can reuse one prediction per retained same-label input and weight it by its recorded eligible provenance multiplicity. It measures retained record-frequency weighting, not the full original traffic after ambiguous/T0-linked exclusions, and cannot recover unseen excluded predictions. Keep it distinct from the primary unweighted endpoint and retain whole-component uncertainty.

Choose the extra evidence required by the intended claim. Do not add every alternative or pick the one that gives favorable final method rankings.

## 6. Claims to avoid

- “All exact-feature matches are leaked source records.”
- “Quarantine repaired ground truth.”
- “The curated prevalence is operational prevalence.”
- “A low retained source count means the raw attack had few flows.”
- “Changing preprocessing until poisoning is strong is a robustness check.”

The useful outcome is an explicit, reproducible benchmark with an honest target population. General concern about evaluation pitfalls is established prior work; it is not this study's novelty by itself. [Arp et al., USENIX Security 2022](https://www.usenix.org/conference/usenixsecurity22/presentation/arp).
