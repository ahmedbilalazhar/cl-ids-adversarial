## Interpretation

- Legacy CICIDS artifacts have no row IDs. Source-level split and cross-task disjointness cannot be certified from them. Their results remain executed, not manifest-validated; rebuild v2 artifacts before claims.
- UNSW and IoT v2 train/test row IDs are positions within different source files. The separate-pool source split is disjoint by construction, while duplicate content across those files still poses a memorization risk.
- CICIDS Friday has substantial exact train/test content overlap in its legacy tasks. Do not interpret its current test accuracy as independent generalization without a duplicate-disjoint sensitivity analysis.
- The duplicate-disjoint CICIDS arm removes repeated raw feature+label rows globally, then excludes any remaining post-scaling test match on FEATURES (labels ignored, signed zeros normalized) against all training tasks. It is a distinct protocol, not a repair of historical scores. See `docs/cicids_cross_file_audit.md` for original-CSV cross-file content fingerprints.
- Pooled cross-split counts complement per-task matching: per-task counts miss test rows that match a *different* task's train rows, and feature+label counting hides feature matches under conflicting labels. The feature-only count is the conservative memorization indicator; identical features do not establish common raw-flow identity.
- `flow_order` is a within-file, per-class capture-order proxy. It does not define a globally chronological deployment stream.
